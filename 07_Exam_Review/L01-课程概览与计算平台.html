讲解 · 课名里的 "Applied" 是什么意思

"Applied（应用）"这个词是有信息量的。计算化学大致分两支：

  • Method development（方法开发）：发明新的近似、新的泛函、新的算法。做这个要写代码、推公式。
  • Applied / production（应用）：用现成的软件包（Gaussian、ORCA、VASP…）去回答一个真实的化学问题。

这门课是后者。所以理论部分的目标不是让你能自己写一个量化程序，而是让你在看到 #p opt b3lyp/6-31G(d) 这一行输入时，知道每一个关键词背后省略了什么近似、这个近似在什么情况下会崩。

讲解 · 这七条其实是一条主线

初学者看这个大纲会觉得是七个互不相干的题目。其实它是一条精度阶梯，从最粗糙爬到最精确，每爬一级就把上一级的一个近似去掉：

层级做了什么近似典型体系规模
力场 (MM)完全放弃电子，把分子当成弹簧连起来的小球10⁵–10⁷ 原子（蛋白质、聚合物）
半经验保留电子，但双电子积分大部分靠参数拟合10³ 原子
Hartree–Fock保留电子，双电子积分全算，但用平均场：每个电子只感受到其他电子的"平均云"10² 原子
DFT与 HF 同形式，但用近似泛函把"相关能"补回来一部分10²–10³ 原子
MP2 / CCSD显式地把电子的瞬时躲避（相关运动）算进来20–100 原子
Full CI不做任何波函数近似（只剩基组不完备）3–4 个原子

整门课的核心情节就是："电子相关（electron correlation）"这四个字。HF 把它丢掉了，后面所有方法都是在想办法把它捡回来，代价是计算量爆炸。第 4 讲整讲都在讲这件事。

拓展 · "粗粒化 (Coarse-Grained)" 是什么

全原子力场里，一个 CH₂ 是 3 个粒子（1 个 C + 2 个 H）。粗粒化力场把整个 CH₂ 当成1 个粒子（bead，珠子），参数重新拟合。粒子数少了 3 倍，但更关键的是：粒子重了、相互作用软了，积分步长可以从 1 fs 拉到 20–40 fs，于是能模拟的时间尺度直接跳两三个数量级（从 ns 到 μs–ms）。代表是 MARTINI 力场，做膜蛋白、脂质体、聚合物自组装的标配。代价是丢掉了化学细节——粗粒化模型里没有"键的断裂"这回事。

拓展 · 名词解释（这些词后面会一直出现）
  • 几何优化 (geometry optimization)：在势能面上找一个梯度为零的点（能量最低点）。你给一个初始结构，程序反复挪原子直到力≈0。
  • 振动频率 (vibrational frequency)：算能量对坐标的二阶导数（Hessian 矩阵），对角化后得到简正模式。它的用途不只是模拟红外光谱——更重要的是判断你优化到的到底是极小点还是过渡态：全是正频率 = 真极小点；有 1 个虚频（程序打印成负数）= 一阶鞍点 = 过渡态。
  • BS-DFT (Broken-Symmetry DFT，破缺对称 DFT)：算双核金属配合物里两个未成对电子是铁磁（平行）还是反铁磁（反平行）耦合的技巧。第 3 讲 p45 会提到它和交换积分 K 的关系。
  • TD-DFT (Time-Dependent DFT，含时密度泛函)：算激发态能量（→ UV-Vis 光谱）最常用的方法。
  • 赝势 (pseudopotential) / ECP (Effective Core Potential，有效核势)：把重原子的内层电子换成一个等效势函数，不再显式计算。既省钱，又顺手把相对论效应塞进去了。

p7什么是计算化学？

原文翻译

计算化学是一个（相对新的）研究领域，其目标是通过使用计算机和粒子间相互作用的基本定律来回答化学问题。

例子：一个典型的化学反应有很多未知量：

  • 找到最合适的反应物
  • 找到最合适的催化剂
  • 反应条件（温度、压力、溶剂等）
  • 把新化合物从反应混合物中分离出来
  • 找出它的物理性质：分子结构与晶体结构、势能面、熔点、EPR 谱、UV-VIS、IR、NMR 和拉曼谱等
  • 建立反应机理，获得新的理解/洞察
  • 理解反应动力学，使其能放大到工业应用

示意图：A + B + 催化剂 → 产物 + C + D + E + …

讲解 · "基本定律"具体指哪一条

这里说的 "fundamental laws of interaction between particles"，在整门课里其实只有一条：库仑定律（带电粒子之间的静电作用）。加上量子力学的运动学（薛定谔方程）和费米子的反对称性（泡利原理），整个分子的行为原则上就完全确定了。

分子体系的完整非相对论哈密顿量（第 2 讲 p77 会正式给出） Ĥ = T̂核 + T̂电子 + V̂核-核 + V̂核-电 + V̂电-电
符号名称物理含义
Ĥ哈密顿算符体系的总能量算符。头上那个尖帽子 "^" 表示这是一个"算符"（operator，一个作用在函数上的操作），不是普通的数。
T̂动能算符粒子运动带来的能量
V̂势能算符粒子之间的静电相互作用能，全部来自库仑定律

为什么这么简单的东西会难？因为最后那一项 V̂电-电（电子之间的排斥）把所有电子的坐标纠缠在一起，方程无法分离变量。整个量子化学的历史，就是想尽办法处理这一项的历史。第 2 讲 p61 会正式说这件事。

拓展 · 计算化学在真实科研里的三种用法
  1. 解释 (interpretation)：实验做出来了但不知道为什么，算一下轨道/电荷/过渡态来解释。这是目前多数论文的用法。
  2. 预测 (prediction)：实验还没做，先算一遍决定该不该做。要求精度高得多，风险也高。
  3. 反推 (assignment)：谱图上有个峰不知道归属，算几个候选结构的理论谱去对。NMR 化学位移、IR 频率、UV-Vis 跃迁都常这么干。

拓展 · 榜单里几个词的意思
  • AM1 / MNDO / PM6：半经验方法家族。它们的共同思路是——保留 HF 的框架，但把最贵的双电子积分要么直接扔掉（NDDO 近似：只保留同一原子上的），要么用实验数据拟合的参数代替。速度比 HF 快几个数量级，代价是只对参数化过的元素/键型可靠。第 3 讲 p62 会提到"半经验方法基于对双电子积分的部分忽略"。
  • GIAO (Gauge-Independent Atomic Orbital，规范不变原子轨道)：算 NMR 屏蔽常数时，磁场的矢势有"规范自由度"，用有限基组会导致结果依赖于你把坐标原点放哪。GIAO 让每个基函数自带一个与位置相关的相因子，从而消除这个依赖。今天所有软件算 NMR 默认都是 GIAO。
  • NBO (Natural Bond Orbital，天然键轨道)：把离域的正则分子轨道（第 3 讲 p46、p61 会讲）转换成化学家熟悉的"孤对电子、σ 键、σ* 反键"的定域图像，从而能定量讨论"超共轭"、"负超共轭"这类概念。

拓展 · Heitler–London（1927）为什么重要

它是第一个用量子力学解释"化学键为什么存在"的计算。对 H₂，他们写的波函数是

ΨHL = χA(1)χB(2) + χB(1)χA(2)
符号名称含义
χA原子轨道A 原子上的 1s 轨道（希腊字母 chi，念"卡伊"）
(1)电子编号括号里的数字是电子的编号，代表这个函数以电子 1 的坐标为自变量

意思是"电子 1 在 A 原子、电子 2 在 B 原子"和"反过来"这两种情形的叠加——纯共价，没有离子项。这就是价键理论 (VB) 的源头。

而分子轨道理论 (MO) 给出的 ΨMO 展开后是 50% 共价 + 50% 离子（第 4 讲 p19 会精确地推这一步）。这两个理论的差别正是第 4 讲的核心情节：MO/HF 在解离极限下因为强行保留 50% 离子项而给出错误的能量，CI 通过混入双激发把离子项消掉，从而修复它。所以这条 1927 年的记录不是历史花边，它是第 4 讲 p17–21 的伏笔。

p12未来发展方向

原文翻译
  1. AI / 机器学习 / 深度学习 + 计算化学 → 有可能以比常规 DFT 快 10000 倍以上的速度得到 DFT 精度的结果 → 允许更充分地扫描相空间、快速预测新材料/现象/反应性/性质 → 加速新分子与新材料的合成与发现
  2. 弱相互作用的准确描述：如范德华力、色散、长程相关
  3. 分子晶体的晶体结构与声子谱的准确预测
  4. 非平衡量子动力学，即同时求解电子与原子核的薛定谔方程（非 Born–Oppenheimer）
  5. 面向量子处理器的计算方法及各类混合方法的发展

讲解 · 逐条说清楚它在解决什么痛点

1. 机器学习势 (MLIP / NNP)

痛点：DFT 算一个 100 原子体系的单点能要几分钟；做分子动力学要算几百万步，根本跑不动。

做法：用几千个 DFT 算好的构型训练一个神经网络，输入是原子坐标，输出是能量和力。训练好之后，一次预测只要毫秒。代表工作：ANI、SchNet、NequIP、MACE，以及近年的通用势 M3GNet、MACE-MP-0、DPA。

本质：它没有解薛定谔方程，它是在拟合势能面。所以它对训练集覆盖不到的化学环境（比如没见过的元素组合、断键中间态）会给出不可靠的结果，而且往往不会报错。

2. 弱相互作用与色散

痛点：HF 和绝大多数常规 DFT 泛函从根本上算不出伦敦色散力。原因是色散来自"两个分子的电子云瞬时涨落的关联"，而 HF 是平均场（没有瞬时涨落），常规 DFT 泛函是"局域/半局域"的（只看某一点及其附近的密度，看不到远处）。

后果：不加修正的 B3LYP 算不出 π–π 堆积、算不出石墨层间结合、算不准蛋白-配体结合能。

做法：Grimme 的 DFT-D3 / D4 经验修正——直接加一项 Edisp = −Σ C6/R⁶（配一个阻尼函数防止短程发散）。你在第 3 讲 p5 的 Gaussian 输出里会看到 Adding Grimme-D3(BJ) dispersion energy 这一行，说的就是这个。

3. 晶体结构预测 (CSP) 与声子

痛点：同一个分子可以结晶成好几种晶型（多晶型 polymorphism），而不同晶型的溶解度、稳定性可以差很多——这在制药业是生死攸关的（Ritonavir 事件：药物上市后突然出现一个更稳定的晶型，导致全球召回）。而不同晶型之间的能量差常常小于 1 kJ/mol，比目前方法的误差还小。

4. 超越 Born–Oppenheimer

痛点：BO 近似（第 2 讲 p78 详解）假定电子瞬间跟上原子核。但在"锥形交叉 (conical intersection)"附近，两个电子态的势能面靠得极近甚至相交，BO 彻底失效。而光化学、荧光、光合作用、视觉的第一步（视黄醛异构化）全都发生在这种地方。

5. 量子计算

为什么量子计算机天生适合量子化学：Full CI 的计算量随体系呈阶乘增长（第 4 讲 p40 标度表里写着 O(n!)），因为要在指数大的希尔伯特空间里做线性代数。而量子比特本身就存活在指数大的希尔伯特空间里——用量子系统模拟量子系统，是 Feynman 1982 年提出量子计算机的最初动机。代表算法：VQE（变分量子本征求解器）、量子相位估计。目前受限于噪声，还只能算 H₂、LiH 这个级别。

p13–14计算机的结构

原文翻译

一块主板集成以下部件：

  • CPU（一个或多个），包含：若干计算核心 (cores)、本地缓存 (cache) 内存（非常快）
  • 活动 RAM 内存（访问快）
  • 硬盘存储（访问慢）
  • 显卡（含自己的 GPU 和显存）
  • 外围部件

讲解 · 一个从慢到快的金字塔

你只要记住一个概念：存储器是分层的，越快越小越贵。数据必须一层层往上搬才能被 CPU 用到。

拓展 · 为什么这跟量子化学有关

因为量子化学最核心的数据结构——双电子积分（第 3 讲 p62）——数量是 N⁴/8 量级（N = 基函数个数）。一个中等分子，N = 500，就是约 8×10⁹ 个数，双精度存储要 约 60 GB。放不进缓存，勉强放进 RAM，一旦放不下就得往硬盘倒——速度立刻掉两个数量级。

这就是为什么会有 "direct SCF"（第 3 讲 p63）：与其存下来再读，不如每次要用的时候现算。因为现在 CPU 算得比内存搬得快。

p15–17计算机集群 (Cluster) 的结构

原文翻译

结构：一个 HEAD NODE（头节点/登录节点）+ 一台 Interconnect switch（互联交换机）+ 若干 NODE-01…NODE-16（计算节点）。

特点（以 NSCC 为例）：

  • 异构互联 (Heterogeneous interconnect)：节点之间的数据传输慢，同一节点内处理器（核心）之间的数据传输快
  • 相当便宜：集群的价格只比所有节点价格之和略高。可以做大规模部署
  • 容错：如果一个节点没有响应，可以单独把它关掉，不需要关停整个集群
  • 通常运行 Linux 操作系统

讲解 · 头节点 vs 计算节点：新手最常犯的错

这是最容易被骂的错误

永远不要在头节点（登录节点）上直接跑计算。头节点是全系几十上百个人共用的，你在上面直接敲 g16 input.gjf，会把所有人的登录卡住，管理员可能直接封你的账号。正确做法是写一个提交脚本（p41 有模板），用 qsub 交给调度器。

拓展 · "异构互联"对你的实际影响

讲义反复强调节点内快、节点间慢。这直接决定了你申请资源时该怎么写：

  • select=1:ncpus=24 —— 要 1 个节点的 24 核。对 Gaussian 来说这几乎总是正确的选择，因为 Gaussian 的常规并行是共享内存（OpenMP/Linda），跨节点效率差（p2 的 Gaussian 表格明说"DFT 最多扩展到 32 核"）。
  • select=4:ncpus=24 —— 要 4 个节点共 96 核。只有当程序用 MPI 且通信量小时才划算（VASP、NWChem 可以）。

新手常见的心态是"多要核 = 算得快"。实际上要多了往往更慢：核多了通信开销上升，而且排队等待时间也变长（调度器要凑齐 4 个空闲节点比凑 1 个难得多）。

p18共享内存超级计算机（如 IBM Blue Gene/Q）

原文翻译

商用超算（如 Blue Gene/Q）拥有专有的大规模主板，能够高效地容纳并集成大量处理器和 RAM 内存插槽。

这类超算的价格远高于同等核数的普通集群。

非常大的 RAM 内存和数千个节点的可用性，使得在别处无法完成的独特任务成为可能：大矩阵对角化。

它们运行 UNIX 操作系统，配有一套内部优化的工具。

讲解 · 为什么偏偏点名"大矩阵对角化"

这句话是给量子化学量身定制的。回想一下：对角化一个 n×n 矩阵，计算量是 O(n³)，但内存需求是 O(n²)，而且它非常难并行（p26 的表格明写 "Most matrix factorizations … Parallel execution: HARD"）。

难并行的原因：对角化算法（如 Householder 变换 + QR 迭代）里，每一步都要用到上一步的全部结果，数据依赖是全局的。你可以把矩阵切开分给不同节点，但每一步都要在所有节点之间交换数据——而节点间通信慢得多。

所以：普通集群适合"能切成互不相干的小块"的任务（比如算几百万个双电子积分，每个积分互相独立）；共享内存超算适合"必须整体处理一个巨大对象"的任务（对角化一个巨大的 CI 矩阵）。

拓展 · CI 矩阵到底能有多大

第 4 讲 p15 有张表：一个体系在某基组下，CISD 的组态数是 2 556，CISDTQ 是 391 126，Full CI 到 10 重激发是 30 046 752。矩阵是这个数的平方——3×10⁷ 的平方是 9×10¹⁴ 个元素，双精度要好几个 PB。所以 Full CI 从来不显式存矩阵，而是用 Davidson 迭代法：只求最低的几个本征值，只需要能计算"矩阵乘向量"而不需要存整个矩阵。

讲解 · 延迟 vs 带宽，用一个比喻讲清楚

比喻：从新加坡往北京运货
  • 延迟 = 你下单之后，第一箱货到达北京要多久（比如 3 天）。
  • 带宽 = 之后每小时能到多少吨（比如 10 吨/小时）。

关键：这两个是独立的。一辆装满硬盘的卡车横穿大陆，带宽极高（几百 TB / 几天），但延迟糟糕透顶（几天）。反过来，一条光纤延迟只有几毫秒，但带宽可能只有 1 Gbps。

讲解 · "随机访问会让程序非常慢"是什么意思

这是这一页最实用的一句话。CPU 从 RAM 取数据时，不是一次取一个数，而是一次取一整条 "cache line"（通常 64 字节 = 8 个双精度数）。所以：

  • 顺序访问（a[0], a[1], a[2]…）：取一次 cache line 能用 8 次，只有 1/8 的访问真正付了 100 周期的代价。
  • 随机访问（a[7], a[913], a[42]…）：每次都 miss，每次都付 100 周期。慢 8 倍以上（实际因为预取失效，往往慢几十倍）。
拓展 · NUMA 是什么

表里出现的 NUMA = Non-Uniform Memory Access（非一致内存访问）。现代双路服务器有 2 个 CPU 插槽，每个插槽直接连着自己的一半内存条。CPU-0 访问自己的内存要 100 周期，访问 CPU-1 那半边要 150 周期（得绕道 CPU 间的总线）。

实际影响：如果你的进程被操作系统迁移到另一个插槽，而数据还在原来那半边内存里，性能会莫名其妙掉一大截。HPC 上跑大作业时常用 numactl 或调度器的 place=scatter/pack 选项来把进程钉在特定插槽上，就是为了避免这个。

p20CPU 性能指标：GIPS 与 GFLOPS

原文翻译

CPU 常用的两个性能指标是：

  • GIPS（每秒十亿条指令）——处理器每秒能执行多少条机器码指令。这个指标非常依赖具体架构。
  • GFLOPS（每秒十亿次浮点运算）——处理器每秒能做多少次单精度或双精度乘法。科学计算几乎总是用双精度。

功耗对单台计算机/节点来说不太关键，平均 0.2 kWh。能耗对大型集群是个问题。

新型 ARM 处理器（用于手机和平板）相比 Intel 处理器能耗显著更低（例如新的 Apple M1）。当前排名第一的超算——日本的富岳 (Fugaku)——用的就是基于 ARM 的 A64FX 处理器。

讲解 · 为什么"科学计算几乎总是双精度"

精度位数有效数字典型用途
单精度 FP3232 位约 7 位十进制图形、深度学习
双精度 FP6464 位约 16 位十进制量子化学

为什么量化非要双精度？因为量化算的是"大数相减得小数"。举个真实的例子：

一个中等有机分子的总能量 ≈ −2692.659 129 53 Hartree（第 3 讲 p5 的真实输出）
而一个化学键的能量 ≈ 0.15 Hartree，一个氢键 ≈ 0.008 Hartree
反应的能垒差异要求精度 ≈ 0.0016 Hartree（约 1 kcal/mol，即"化学精度"）

你要在 2692 这个量级上分辨 0.001 的差别，就需要 约 7 位有效数字只用来抵消，剩下的才是有用信息。单精度只有 7 位——全部吃光，一位不剩。所以必须用双精度。

拓展 · 这也是"GPU 在量化里没有想象中好用"的原因

消费级显卡（RTX 40 系等）的 FP64 性能被厂商故意限制到 FP32 的几十分之一，因为游戏和 AI 都只需要 FP32/FP16。真正 FP64 强的是数据中心卡（A100/H100，FP64 大约是 FP32 的 1/2）。所以你不能拿游戏显卡加速 Gaussian。

近年的进展是"混合精度"：用 FP32 甚至 FP16 算积分的大部分贡献，只对数值上重要的部分用 FP64。TeraChem、以及 ORCA 6 的部分模块走的是这条路。

原文翻译

集成电路上的晶体管数量大约每两年翻一番。

现代计算机不断增长的算力，推动着计算化学扩展到更复杂的体系和更精密的理论层次。

讲解 · 摩尔定律在这门课里的残酷含义

摩尔定律说算力每 2 年翻倍。听起来很好——但请对照第 4 讲 p40 的标度表：

方法标度算力翻倍后，能算的体系大多少？

MP2O(N⁵)×21/5 = +15%

摩尔定律给你的算力是指数增长，但方法的开销也是高次幂增长，两者相抵后，"能算多大"只是龟速爬行。等 20 年（算力涨约 1000 倍），CCSD 能算的原子数也只涨到 3 倍。

所以这个领域真正的进步来自算法而不是硬件：把 O(N⁴) 通过 RI 近似降到 O(N³)（第 3 讲 p64）、通过局域化降到接近 O(N)（线性标度方法，如 DLPNO-CCSD(T)）。一个把标度降一阶的算法，抵得上几十年的摩尔定律。

拓展 · 摩尔定律其实已经改道了

2005 年之后，单核频率停止增长（卡在 3–5 GHz，因为功耗随频率急剧上升，散热扛不住）。晶体管数还在涨，但涨出来的都用去堆核数了。后果：你的程序如果不会并行，那从 2005 年到现在它几乎没变快。这就是为什么这门课要花时间教你写 #PBS -l select=1:ncpus=12。

注意这里是微秒级的延迟——1 微秒相当于 Nehalem CPU 上约 2000 个时钟周期。带宽也远低于 RAM 或缓存的带宽。

因此，数据依赖很多的内存密集型计算往往难以在集群架构上运行。把它们跑在单个节点上，可能比在多个节点上并行快得多。

讲解 · 这三页在讲同一件事：并行不是免费的

把 p24 那句话翻译成人话：如果你的计算里各部分需要频繁交换数据，那么"分给更多节点"反而会更慢。

粗略地看一个例子：假设一步计算要 1 μs，而每步之后要跟别的节点通信一次，通信延迟也是 1 μs。

  • 单节点跑 n 步：n × 1 μs = n μs
  • 2 节点各跑 n/2 步，但每步多付 1 μs 通信：(n/2) × (1 + 1) μs = n μs。一点没快。

通信开销不随节点数下降，而计算量随节点数下降——所以总有一个点，再加节点就开始变慢。

拓展 · Amdahl 定律（并行的天花板）

这一页背后的正式定律。设你的程序里有比例 p 的部分可以并行，剩下 (1−p) 必须串行，用 n 个核，加速比是：

Amdahl 定律 S(n) = 1 ⁄ [ (1 − p) + p/n ]
符号名称含义
S(n)加速比用 n 个核比用 1 个核快多少倍
n核数并行使用的处理器核心数
p并行比例程序中可以并行的部分占的时间比例（0 到 1）
1 − p串行比例无论多少核都必须一个一个做的部分

致命的推论：令 n → ∞，得到 Smax = 1/(1−p)。

即使 95% 的代码能完美并行，用无限多个核，最多也只能快 20 倍。而 SCF 里的 Fock 矩阵对角化就是那个难并行的部分。这就是为什么 p2 说 Gaussian "DFT 也只能扩展到 32 核"。

大量的输入输出（IO）操作会显著拖慢集群性能。请按集群管理员的指示，用 "scratch" 文件夹来运行计算。

这是作业里必须做对的一件事

你的 $HOME 是网络文件系统——它挂在另一台机器上，所有节点通过网络访问它。而 Gaussian 一次计算会往硬盘写大量临时文件（.rwf、.int、.d2e），几十 GB 很常见。

如果你在 $HOME 里跑，这几十 GB 的读写全部走网络，不但你的作业慢很多倍，还会拖累整个集群的文件系统，全系的人都受影响。

正确做法：在提交脚本里把工作目录设成本地 scratch。典型写法：

export GAUSS_SCRDIR=/scratch/$USER/$PBS_JOBID
mkdir -p $GAUSS_SCRDIR
cd $GAUSS_SCRDIR
# ...跑计算...
cp *.log *.chk $PBS_O_WORKDIR/    # 算完把结果拷回 $HOME
rm -rf $GAUSS_SCRDIR              # 清理 scratch
拓展 · 各种"盘"的名字对应关系
$HOME你的主目录，有配额（几十 GB），网络挂载，有备份。放代码、输入文件、最终结果。
scratch临时高速盘，容量大（TB 级），没有备份，会被定期自动清空（通常 7–30 天）。放中间文件。
swap严格说不是给用户的：当 RAM 不够时，操作系统把内存内容临时倒到硬盘上。一旦你的计算开始用 swap，速度会掉两个数量级——所以 %Mem 一定要设得小于节点实际可用 RAM。

p26基本运算的标度（BLAS 与 LAPACK）

原文翻译

矩阵分解（SVD、LU、对角化、Householder 等）非常昂贵、难以并行，并且无法从稀疏存储中获益。

运算CPU 开销 / FLOPs内存开销稀疏时开销并行执行
矩阵×矩阵O(n³)O(nnz)更低容易
矩阵×向量O(n²)O(nnz)更低容易
exp(矩阵)×向量O(n²)O(nnz)更低容易
矩阵求指数O(n³)O(nnz)更低容易
大多数矩阵分解O(n³)O(n³)相同困难

公式解析 · 表里的符号是什么意思

符号名称含义
n矩阵维度矩阵是 n×n 的。在量化里 n ≈ 基函数个数 Nbasis
O(·)大 O 记号"渐近标度"。O(n³) 意思是：n 翻倍，时间变 8 倍。它只关心增长趋势，不关心前面的常数因子。
nnz非零元个数number of non-zeros。稀疏矩阵里绝大部分元素是 0，只需存 nnz 个数而不是 n² 个。
FLOPs浮点运算次数加、减、乘、除各算一次。注意区分 FLOPs（次数）和 FLOPS（每秒次数）。

讲解 · 最后一行为什么是灾难

前四行都很友好：矩阵乘法虽然是 O(n³) 的计算量，但内存只要 O(nnz)（稀疏时很小）、而且极易并行（把矩阵切成小块，各块独立算）。

但矩阵分解（对角化就是其中之一）三样全占：

  • 内存也是 O(n³)：因为分解过程中会产生大量新的非零元（"fill-in 填入"）——原本稀疏的矩阵，分解到一半就变稠密了。
  • 稀疏没用：同上，稀疏结构在分解过程中被破坏。
  • 难并行：数据依赖是全局的（见 p18 的解释）。
这一页是第 3 讲 SCF 循环的技术底座

去看第 3 讲 p60 的 SCF 流程图：每一轮迭代都要"对角化 Fock 矩阵"一次。典型的 SCF 要迭代 10–30 轮。所以对角化的开销要乘以 30。

这就是为什么"基组一大就慢得离谱"：N 从 100 增到 200，对角化时间 ×8，双电子积分数量 ×16。

拓展 · BLAS 和 LAPACK 是什么
  • BLAS (Basic Linear Algebra Subprograms)：底层线性代数例程的标准接口，分三级——Level 1（向量·向量，O(n)）、Level 2（矩阵·向量，O(n²)）、Level 3（矩阵·矩阵，O(n³)）。
  • LAPACK：建立在 BLAS 之上的高级例程——解线性方程组、最小二乘、本征值问题（对角化）、各种分解。

为什么要有"标准接口"：因为 Intel（MKL）、AMD（AOCL）、开源（OpenBLAS）各自写了针对自家 CPU 极致优化的实现，但都遵守同一套函数名和参数约定。于是 Gaussian/ORCA 只要链接不同的库，就能在不同硬件上跑出最优性能，源码一行不用改。一个手写的矩阵乘法可能比 MKL 慢一到两个数量级——因为 MKL 用了向量指令 (AVX-512)、缓存分块、多线程。所以科学计算里"永远不要自己写矩阵乘法"。

公式解析 · 管道 | 到底做了什么

Unix 管道 cat file1  |  grep ' and '  |  wc -l
拆开看，数据是这样流动的：
  1. cat file1 → 把整个文件的内容吐出来（比如 40 行）
  2. | → 管道符：把左边命令的标准输出，接到右边命令的标准输入上。不经过磁盘，直接在内存里传
  3. grep ' and ' → 从这 40 行里，只留下包含 " and "（前后带空格）的行，比如剩 12 行
  4. | → 这 12 行继续往右传
  5. wc -l → 数一数收到了几行 → 打印 12
这条命令其实有个陷阱，值得想一想

它数的是"包含 and 的行数"，不是"and 出现的次数"。如果一行里有两个 "and"，只算 1。

要真正数出现次数，得用：grep -o ' and ' file1 | wc -l（-o = only-matching，每个匹配单独输出一行）。

另外 ' and ' 两边的空格是为了避免匹配到 "sand"、"android"、"standard"。更严谨的写法是 grep -ow 'and'（-w = word boundary，词边界）。

if [ -f file4 ];
then rm -rf file4; fi		条件判断[ -f file4 ] 测试 "file4 存在且是普通file"。存在就删掉——避免和上次运行的结果混在一起。

拓展 · 一个真能用的 Gaussian 提交脚本

#PBS -N myjob                              # 作业名字(Name)
#PBS -P personal-$USER
#PBS -q parallel
#PBS -l select=1:ncpus=8:mem=16GB
#PBS -l walltime=24:00:00                  # 最长运行 24 小时,超时被杀
#PBS -j oe

讲解 · $PATH 和 $LD_LIBRARY_PATH（第 2 讲 p95–96 会再讲一遍，这里先说透）

$PATH：操作系统去哪儿找"可执行程序"

当你敲 orca 时，系统并不会搜遍整个硬盘。它只会依次检查 $PATH 里列出的那几个目录，找到第一个叫 orca 的可执行文件就运行。找不到就报 command not found。

echo $PATH
# /usr/local/bin:/usr/bin:/bin:/usr/games       <- 冒号分隔的目录列表

export PATH=$HOME/software/orca_6:$PATH         <- 把 orca 目录加到最前面
which orca                                      <- 确认系统现在能找到它了

注意 $PATH 写在末尾的写法 新目录:$PATH——意思是"新目录优先，但保留原有的所有目录"。如果写成 export PATH=新目录（漏掉 :$PATH），你会把系统所有基本命令都弄丢，连 ls 都用不了。

$LD_LIBRARY_PATH：程序运行时去哪儿找"动态库"

现代程序不会把所有代码都编进自己的可执行文件，而是运行时才去加载共享库（.so 文件，相当于 Windows 的 .dll）。$LD_LIBRARY_PATH 就是告诉动态链接器额外去哪些目录找这些 .so。

ldd $ORCA/orca          <- 列出 orca 需要的所有库,以及找到没有
# libmpi.so.40 => not found        <- 这就是问题所在

export LD_LIBRARY_PATH=$HOME/software/openmpi/lib:$LD_LIBRARY_PATH
ldd $ORCA/orca          <- 再查一遍,应该全部指向具体路径了

典型症状：程序一运行就报 error while loading shared libraries: libXXX.so: cannot open shared object file。讲义 p96 说得很准："这里没什么问题出错了，操作系统只是不知道去哪儿找需要的库。"

拓展 · module 命令：HPC 上的标准解法

module unload Gaussian           # 卸载

module load 干的事就是执行一个脚本，帮你把该软件需要的 $PATH、$LD_LIBRARY_PATH、以及各种专有变量（$GAUSS_EXEDIR 等）一次设好。所以提交脚本里的 module load 一行都不能省——因为计算节点上的环境是全新的，不会自动继承你在登录节点上临时设的那些变量。
